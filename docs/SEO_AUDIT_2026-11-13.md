StayMaint SEO audit — 13 November 2026

The public site has a working technical SEO foundation. All 13 sitemap pages return HTTP 200 and have unique titles and descriptions, canonical URLs, and crawlable content. The audit found improvements in language handling, title composition, missing-page status codes, and social metadata. No site-wide public indexing block was found.

Coverage: reviewed all 79 Next.js page route templates; made 91 distinct live URL checks including all sitemap URLs, representative dynamic routes, private routes, and missing pages; rendered all 13 public pages at a 390 × 844 mobile viewport. Dynamic private records were sampled using placeholder identifiers to verify anonymous access and indexing behavior, rather than enumerating customer records. Backend admin login was checked separately.

This is a technical and on-page audit. It does not establish actual Google index coverage, rankings, backlinks, search demand, or field Core Web Vitals. Search Console is not connected; no numeric SEO or performance score is claimed. Public-page metadata and layout observations were verified against the deployed site, with repository source used to identify likely causes. Website code and deployment were not changed by this audit.

**Checks that passed**

- `/robots.txt` and `/sitemap.xml` are available. Sitemap URLs contain only public canonical pages, with no authenticated dashboard or tenant-specific records.
- The live Cloudflare-managed robots section allows ordinary search crawling. Restrictions on named training crawlers are separate from Google Search indexing and were not treated as an SEO fault.
- All 13 public pages have unique descriptions and unique page titles. No public-page `noindex` was observed.
- All 13 public pages render their content successfully in a browser. The raw streaming HTML also contains a loading H1, but it disappears during rendering; the final visible document has one H1. This was not counted as a duplicate-heading defect.
- Login, authentication, invitations, demo, platform, offline, AI placeholder, report, and dashboard responses tested carry `noindex`; anonymous dashboard requests end at login. Admin login carries `NONE,NOARCHIVE`. Client-rendered platform shells were evaluated for indexing only, not as an authorization audit.
- Sitemap pages are reachable from public internal links. Internal destinations found on those pages were covered by the crawl, except Cloudflare's generated email-protection endpoint, which was outside the application-page audit.
- `https://www.staymaint.com/hotel-cmms/` redirects permanently to the canonical non-www URL. HTTP and the legacy `hotelcarepro.com` domain redirect to HTTPS `staymaint.com` while preserving the sampled path. `/pricing` redirects to `/pricing/` with 308.
- Both referenced social images, `/og-image.jpg` and `/twitter-image.jpg`, return 200. Rendered page images have alt attributes; decorative empty alt text was not treated as missing.
- Homepage JSON-LD and the ten landing pages' FAQPage JSON-LD parse successfully. This confirms syntax only, not Rich Results Test eligibility. Contact/pricing do not require JSON-LD to be indexable.

FAQ markup is not a current Google rich-result growth opportunity: Google retired FAQ rich results in May 2026 and removed its documentation in June. Existing FAQ content remains useful to readers; valid FAQPage markup is not an audit error. See [Google's documented updates](https://developers.google.com/search/updates#june-2026).
